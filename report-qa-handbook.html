Read this first

It is stage one, not the review

This tool catches mechanical faults: spelling, spacing, formatting, identifiers, and content that should never ship. It cannot tell you whether your findings are right, whether a severity is justified, or whether your remediation advice is sound.

A clean result is not sign-off. Every draft still needs someone to read it for argument, accuracy and judgement. Clearing the mechanical faults first is what lets that reading go on the things a rule cannot see.

Read this second

Nothing leaves your computer

There is no upload, no server, no account and no telemetry. The draft you drop in is read into your browser's memory, checked there, and forgotten when you close the tab. It never touches a network.

You can prove it: disconnect from the internet, open the file, and check a report. It works exactly the same.

01 How it runs

The tool is a single file, report-qa.html. Save it somewhere convenient and open it in Edge or Chrome. There is nothing to install and nothing to log into.

A web page is usually a request to a server somewhere. This one is not. Everything the tool needs — the checks, the dictionaries, the code that reads PowerPoint and Word files — is written inside that one file. Your browser runs it locally, the same way it would run any page. When you drop a draft on it, the browser hands the file's contents to code running on your machine. No request is made, so there is nowhere for the draft to go.

This is enforced rather than promised: the file is rebuilt by a script that refuses to produce a page containing a network call, an external script or a link to anything outside itself. If someone added one, the build would fail rather than ship.

Keeping it current. The version and check count are printed at the foot of the tool. To update the team, replace the one file wherever you keep it — everyone picks up the new checks the next time they open it.

02 What it can and cannot do

It can

  • Find credentials, another client's name, and text that was never meant to ship
  • Catch a previous client's name hiding in the slide master, where reading the deck would not show it
  • Read speaker notes, comments, tracked changes and document properties
  • Check Common Vulnerability Scoring System (CVSS), Common Vulnerabilities and Exposures (CVE), NIST CSF and ISO/IEC references are well formed and current
  • Hold a report to one dialect, one set of terms and one house style
  • Point at the exact words at fault, on the exact slide or line
  • Write its findings into a copy of the deck as PowerPoint comments

It cannot

  • Tell you whether a finding is correct, or whether you have missed one
  • Judge whether a severity or a risk rating is justified
  • Know whether your remediation advice would actually work
  • Understand the client, the engagement or the politics of the report
  • Check anything in an image, a screenshot or a chart
  • Read a PDF — and it refuses to try, on purpose
  • Replace a second pair of eyes

On false positives. A rule that fires on correct prose is worse than a missed nit, because it teaches people to ignore the tool. The checks are written conservatively, but they will still be wrong sometimes. When one is, set it aside (section 06) — do not change good writing to satisfy a rule.

03 Before your first check

Open Engagement settings and fill them in. They describe the engagement rather than the file, they are remembered on your computer, and they apply to every draft until you change them. Three checks cannot run without them, so an empty field quietly narrows the whole pass.

SettingWhat it doesIf you leave it blank
English Fixes the report to British or American spelling. The dialect is guessed from the draft, which is unreliable on a short deck.
This client's name Checks the report actually names them. Nothing notices a template field nobody filled in.
Other clients' names Catches a previous client surviving in a copied deck, including in the slide masters. Template leakage goes unreported — the single most damaging thing this tool finds.
Required marking Checks your classification marking is present and consistent. The marking is not checked at all.

04 Running a check

  1. Drop the draft onto the page, or click to choose it.

    PowerPoint, Word, Markdown or an HTML page. Nothing is uploaded.

  2. Read the verdict.

    One line at the top: whether anything in the draft must not reach a client.

  3. Work the blockers and majors, which open by default.

    Minors and nits start collapsed so the list stays one screen.

  4. Set aside anything that does not apply.

    The counts, the verdict and every export follow your decisions.

  5. Hand the findings back, then read the draft yourself.

    This is the step the tool cannot do for you.

05 Reading the findings

Every finding quotes the draft's own words with the run at fault highlighted, so you can match it against the slide in front of you. Whitespace faults are highlighted too — a highlighted blank is the only way a double space is visible at all.

The four levels

Blocker12 checks
Must not reach a client at all.
A credential, another client's name, an unresolved comment, a tracked change, an internal remark in the speaker notes. Fix before the draft leaves the building.
Major30 checks
Wrong, or reads as wrong to the client.
A missing section, a cross-reference that goes nowhere, a CVSS score that contradicts its own label, an acronym never expanded.
Minor35 checks
The draft disagrees with itself.
Spelling, capitalisation, dashes, spacing. Each one is small; together they are what makes a report look unchecked.
Nit30 checks
A preference rather than a fault.
Wordiness, hedging, passive voice. Fix if you have the time, ignore it if you do not.

Finding your way around

Findings are gathered under the check that raised them, one card per check, in runs headed Blocker, Major, Minor and Nit. A check that fired eight times is one card carrying a count and a preview of the flagged words, which is often enough to act on without opening it — open it for the eight places. Each card names, along its foot, why the check exists and which family it belongs to.

Show filters to one level; Blocker on its own is the go/no-go view, and clicking it again clears the filter. Expand all opens everything. Printing opens every group first, so nothing vanishes from a PDF.

06 Setting findings aside

No rule set is right about everything, so you have the last word. Ignore on a finding stops that flagged text being reported by that check. Ignore check sets the whole check aside for this draft. Both are judgements about this report, not edits to it.

Nothing you set aside is simply gone. It collects in an Ignored section at the foot of the list with a Restore on each, the running total sits under the verdict, and every copied format states how many were left out. A QA pass whose exclusions are invisible is one nobody can check.

Your decisions last as long as the page is open, and survive re-checking the same draft after a round of edits. They are deliberately not saved to disk: doing so would write text from a client deliverable into browser storage, and the promise this tool makes is that the draft stays on your machine.

07 Handing findings back

Copy puts the findings on your clipboard in the shape the next person needs. All four quote the flagged text, because "line 42 has an American spelling" sends the author hunting and Found: "color" does not.

ButtonGives you
For commentsOne block per finding, to paste into the comment on that slide or paragraph.
SummaryOne line per finding, blockers first, to attach to the mail back to the author.
Blocker listOnly what stops the draft being issued.
Full reportThe complete report in Markdown, for a review thread.

Writing comments straight into a deck

For a PowerPoint file, Download deck with comments saves a copy carrying one real PowerPoint comment per finding, on the slide it came from. The consultant opens it, works through the comment pane and resolves each one — no transcribing by hand.

It writes a copy. The file you dropped in is read and never written to. Comments already in the deck are kept, along with whoever wrote them, and anything you set aside is left out. Word files are not supported for this yet: Word anchors comments to exact runs of text rather than to a page, which is a harder problem.

FormatSupport

.md, .txtFully supported.
.htmlConverted to text and checked.
.pdfRefused on purpose. Pulling text back out of a PDF garbles spacing and line breaks, so a check on it would report faults that are not in your document and miss ones that are. Check the file you made the PDF from.
.doc, .pptRefused. Save as the modern format first.

Report QA is the mechanical half of a two-stage review. It is deliberately narrow: it reports only what a rule can be sure of, so that the judgement a report actually needs stays with the person doing the review.
